# سازگاری با SCADA: ارسال اطلاعات دستور کار، فرمان‌های ماشین و قرقره

«شروع اجرا» در SCADA حدود ۲۰ تا ۳۰ فرمان نوشتن را **پشت‌سرهم** برای یک ماشین می‌فرستد (شماره سفارش، تاریخ، اپراتور، مشخصات…
و آخرین فرمان یک پرچم «داده‌ها آماده است»). این تغییرات firmware را برای آن آماده می‌کند. قرارداد MQTT (topic و JSON) **تغییری نکرده**.

## تغییرات

| موضوع | قبل | حالا |
|---|---|---|
| صف فرمان | یک خانه؛ فرمان بعدی قبلی را بازنویسی می‌کرد و یک پیام در هر چرخهٔ حلقه پردازش می‌شد (۲۱ فرمان ≈ ۲۰ ثانیه) | صف FIFO با `CMD_QUEUE_MAX=48`؛ همهٔ پیام‌های رسیده خوانده (`MQTT_DRAIN_MAX_LOOPS`) و به ترتیب نوشته می‌شوند؛ پرچم آماده آخر می‌رسد |
| دقت اعداد بزرگ | `float` (۲۴ بیت): شمارهٔ سفارش `140500001` → `140500000` | محاسبهٔ raw با `double` و گرد کردن؛ مقدار خارج از بازه clamp می‌شود |
| `uint32` | ناشناخته → بی‌صدا `uint16` | نوع `uint32` (۲ رجیستر، big-endian) برای خواندن و نوشتن |
| آدرس بیتی | `"48310.3"` → `atol` بیت را دور می‌ریخت | `"48310.3"` یعنی بیت ۳ رجیستر 48310 (فقط `bool` روی holding)؛ خواندن بیت، نوشتن با read-modify-write |
| planner | فقط رجیستر مجاور؛ رجیستر تکراری بلوک جدا؛ سقف ۸ بلوک | رجیسترهای تکراری ادغام؛ فاصله تا `PLANNER_MAX_GAP=4` پر می‌شود؛ سقف ۱۶ بلوک |
| telemetry | همهٔ مقدارها `float` | اعداد صحیح بدون scale به‌صورت عدد صحیح دقیق ارسال می‌شوند |
| حلقهٔ اصلی | بعد از هر چرخه `delay(poll_interval)` | اگر فرمانی پردازش شد یا مانده، بدون خواب چرخهٔ بعد |

## نکته‌های استفاده
- پروفایل (`data/config.json`) را از SCADA دوباره export کنید و `uploadfs` بزنید تا تگ‌های جدید (`Cmd.*`, `Reel.*`, `Job.*`) و `tag_uuid` برسند؛ `access` تگ‌های قابل‌نوشتن باید `read_write` باشد.
- اگر صف پر شود فرمان رها می‌شود (فقط لاگ سریال)؛ `CMD_QUEUE_MAX` را بالا ببرید.
- گسترش فاصلهٔ planner رجیستر استفاده‌نشدهٔ بین دو تگ را هم می‌خواند؛ اگر PLC آن‌ها را ندارد `PLANNER_MAX_GAP` را ۰ کنید.
